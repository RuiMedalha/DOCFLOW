## 5. Validadores NIF / IBAN

Path: `apps/api/src/common/validation/tax-id.validator.ts`

The file exports two pure helpers. **The names diverge from the user's spec** —
the requested `validateNifMod11` / `validateIbanMod97` are actually exported as:

- `isValidPortugueseNif(input: string): boolean` (53) — mod-11 checksum for PT NIFs.
  Accepts `PT515208566`, `515208566`, `PT 515 208 566`. Returns false for
  foreign NIFs like `ES14219836`. Strips `^PT/i` prefix and whitespace.

- `isValidIban(input: string): boolean` (98) — ISO 13616 mod-97. Accepts
  `ES2501825699690201515634`, whitespace-padded, lowercase. Reorders country+check
  digits to the end, letter→number map A=10..Z=35, chunked mod-97 to avoid
  safe-integer overflow.

Usage example (from `extraction.service.ts:62`):
```ts
import { isValidPortugueseNif } from "../../common/validation/tax-id.validator";
// (used by the extraction filename-heuristic guard + AI-vs-QR disagreement logger)
```

Also exports a separate `isValidNif` / `isValidIban` pair from the
`@docflow/shared` package used by `extraction.service.ts:14-19`. The shared
helpers normalise differently (parsing PT NIFs from country-prefixed VAT IDs),
and `tax-id.validator.ts` is the L1 home for **structural** mod-11/mod-97
checks. Both are present — pick the API file when the pipeline needs the
strict structural checksum.

There is a spec covering them at
`apps/api/src/common/validation/__tests__/tax-id.spec.ts`.
